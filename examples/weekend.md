# Ship a side project in one weekend

Most side projects die in the planning doc. This is the two-day plan that gets one live.

## Friday night: scope it
1. Pick one problem: something you hit this week, not a someday idea
2. Write the README first: if you cannot explain it in three lines, cut it
3. Sketch the smallest demo: one command, one screen, one result

## Saturday: build the core
- Build the core loop: input in, result out, nothing else
- Write one test: the one that proves the result is right
- Deploy it somewhere free: a static host, a gist, a release
- Stop at 8 pm: tired code costs you Sunday

## Why it works
Small scope beats big plans. You finish because the finish line is close enough to see. Shipping once makes the second project twice as fast.

## Sunday: tell people
| Where | What to post |
| --- | --- |
| Your README | A screenshot of the result |
| A forum you read | The problem it solves, in one line |
| A friend | The link, and one question |
